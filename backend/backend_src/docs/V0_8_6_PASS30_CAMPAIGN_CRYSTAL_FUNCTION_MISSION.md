# v0.8.6 — Pass 30 Campaign Crystal + Function Unlock + Story Mission 80001

This is a narrow Campaign-adjacent expansion of the existing v0.8.5 domain-repository skeleton. It does not add new MID discovery, Campaign repeat-drop RNG, stamina spending, broader mission chains, or PvP/Institute behavior.

## 1. Campaign first-3-star Crystal

`tools/build_campaign_economy_meta.py` now extracts `campaign.lua.star_gift` through the effective writable-over-APK source resolver. `WorldRepository` compares the persisted prior star count with the submitted result and grants `star_gift` only on the first transition to three stars. The Crystal grant is part of the same `EconomyRepository.apply_campaign_win()` scalar transaction as Campaign Mana/player EXP. MID114 exposes the source per-result scalar as `star_crystal`; the request-scoped `ResponseProjector` carries the new cumulative Crystal balance in `economy_.crystal`. The committed MID114 receipt prevents a duplicate result from minting the gift twice.

For source row 100004 the effective metadata records `star_gift=30`.

## 2. Level-driven FunctionID synchronization

`tools/build_function_unlock_meta.py` parses effective `function.lua` using the same level-spec interpretation as `FunctionOpenTable.lua`. `FunctionUnlockRepository` persists FunctionIDs whose player-level threshold is crossed by an Economy-owned level change. The Phase-1 compatibility policy deliberately does not backfill all old level-1 functions; it emits only `before_level < required_level <= after_level`.

`EconomyRepository` invokes the Function repository after a player-EXP level increase. `ResponseProjector` diffs persisted `func_ids` and attaches added IDs as `new_funcs_`. This matches `Backend.extraWebResponseCheck_()`, which passes `new_funcs_` both into the ECONOMY level-up news and `SelfPlayer:onNewFuncOpen()`. Effective FunctionID 33 (`Upgrade Skill`) has player-level threshold 7, so the normal fresh Campaign progression can now unlock it without special-casing the Skill handler.

## 3. Canonical Story Mission 80001

Pass 30 introduces `MissionRepository` as the canonical owner for the first Story mission only. Transitional `PlayerState.missions` remains for unimplemented mission families; Story 80001 persistence lives in `mission_state`.

Effective source metadata records:

- mission type 4 (Story);
- requirement Campaign 100004 x1;
- source chain root previous=0, next=80003;
- active reward-change columns selected by FunctionID 84 `open_control=1`;
- reward Mana 15000 + Lightin contract `40001004 x10`.

A successful canonical clear of Campaign 100004 marks 80001 complete and returns the changed row in `story_mission_` so an already-loaded Task model updates immediately. MID2736 type 4 loads the canonical row. MID161 claim is idempotent and pre-snapshots Mission, Backpack, and touched Economy/Function fields; it grants Mana through `EconomyRepository`, adds the contracts through `InventoryRepository`, marks the mission claimed, stores a claim receipt, and saves once. `awards` uses the source display contract (`table_id=-2` for Mana plus `40001004`) while cumulative Mana is synchronized through `economy_`.

Pass 30 intentionally does **not** implement Mission 80003 semantics yet.

## Effective-source requirement

All new source-derived constants are generated by resolving each relative source path as:

1. recovered writable `downloaded-assets/output/src_64/<path>` when present;
2. otherwise APK `app-assets/output/assets/src_64/<path>`.

The generated Campaign, Function, and Story-Mission metadata are stamped `_meta.source_resolution=effective_merged`; runtime repositories fail closed if their metadata lacks that provenance.

## Deliberate boundaries

Still unresolved/deferred:

- Campaign Energy/stamina deduction and defeat-cost timing;
- normal repeat-clear Campaign dropbox RNG/increase-rate behavior;
- the Story Mission chain after 80001;
- MID59 Lightin stone/contract summon;
- MID118 chapter-star chest/bonus claim;
- advanced Hero progression and broad non-Campaign systems.

## Validation

Assistant validation for this release is static only: all Python files compile and JSON metadata parses. No Flask/HTTP integration tests, selftests, APK/ADB/emulator, or gameplay execution are run. User-device runtime remains authoritative.
