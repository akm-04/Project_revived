# Backend system map

Generated by `tools/system_map.py` from the Go source, `docs/architecture/CANONICAL_TABLE_OWNERSHIP.json`,
`docs/i9/I9_MODE_SURFACE_V1.json`, the virtual-client scenarios, and two committed inputs:
`client_mid_callers.json` and (when a suite has run) `scenario_coverage.json`.
Do not edit generated files by hand.

## Files
- `INDEX.json` – one row per `internal/application/<system>` with counts and purpose, plus
  `mid_to_system` and `table_to_system` lookups.
- `systems/<system>.json` – one system.
- `FINDINGS.json` – review leads, not verdicts.
- `client_mid_callers.json` – client MIDs, names, files, `senders` (a `request(` on the same line), `other`.

## Fields
- `mids` – registered stock HTTP MIDs: MID number, client name. Dispatcher files and wiring files
  are listed once per system (`dispatcher_files`, `wiring_files`).
- `pushes` – realtime S2C registrations attributable to the system.
- `tables.owned` / `tables.read` – table names only. `content` is the `content_*` subset of `read`.
  A store package wired by `SHARED_STORE_SYSTEMS` or more systems is shared: its tables stay with the
  system that owns the store by name, or the table's ownership `owner`, or else only `stores` links it.
- `calls` / `called_by` – system → callable names crossing that import edge. Derived from exported
  functions/methods with parameters that have a single defining application system and a matching
  `.Name(` use in the caller. Interface-mediated and ambiguous names are omitted; see the gap list.
- `decorated_by` – registration wrappers such as `observing`.
- `facts` – `emits` from `Facts.RecordTx`/`objective.Fact{Kind:…}` literals; `reads` from the
  missions (i5) accepted-kind checks and Adventure's `EventForFactKind` map.
- `login` – MID 1 / lobby contributors and overlays: contributor types in the bootstrap composition,
  plus `OverlayMID1`, `OverlayRosterTx`, `ReconcileCharacterLogin`, `ReconcileDirectoryTx`.
- `background` – `go runReconcile` loops (gxb-api) and River enqueues/workers.
- `locks` – `*LockRank` constants referenced by the system and its stores, with the tx profile
  `LockTimeout` in milliseconds. This is what is taken, not a proven order.
- `tests.scenarios_naming` – scenarios that name a system MID in text; not coverage.

## Limits
- Calls through interface ports are only captured when the method name is unambiguous and used.
- Fact kinds carried in variables or content rows are not enumerated.
- Adapter-owned bootstrap contributions with several application imports are omitted.
- Soft refusals with a variable `error_code` are not listed.
- `show missions` aliases to `i5`: there is no `internal/application/missions` package.

## Commands
```
python3 tools/system_map.py --write
python3 tools/system_map.py --check
python3 tools/system_map.py show <system|mid|table>
python3 tools/system_map.py --refresh-client <src_64>
python3 tools/system_map.py --refresh-coverage <one-mid-per-line-file>
```
`--check` fails only on stale generated files. `--refresh-coverage` records the MIDs and the current
backend commit; a stale coverage file is an input, not a check failure.
