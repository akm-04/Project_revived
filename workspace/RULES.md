# RULES (GXB1 reconstruction) — read this first, every session and after every compaction

This page replaces PROJECT_AGENT_RULES.md (owner, 2026-11-27). Owner rulings are in work/RULINGS.md; tool detail is in
the guides linked below. When two texts disagree: the owner's newest instruction > registered contracts and gates >
this page > work/RULINGS.md > lane docs > checkpoints. A rule that is wrong gets fixed here, never worked around.

## Start / resume
1. `.toolchain/bin/python3 -B ops/workspace_sync.py --doctor` (status + anything stale; until it exists: ops/state.py).
2. work/LANES.md: which lanes exist, who leads them, their folders and last checkpoints.
3. Your lane: START_HERE.md -> HANDOFF.md -> `ops/lane.py task list <lane>`. The lead also reads work/LEAD_QUEUE.md.
4. Continue without asking. A new session is not a reset of the permissions already given.

## Truth
- The client source (tmp/virtualclient/src_64) decides wire shapes; registered contracts decide policy; the sealed
  PassMap (hot/ENTRY.md of the sealed authority) decides authority. Never invent a mechanic, id, owner or reply;
  carry UNKNOWN until a source settles it. Separate designed / implemented / tested / live-tested / owner-confirmed.
- Every claim cites evidence (path:line, commit, command output). Never weaken a test to make it pass.

## Roles
- **Owner**: rulings, pushes, device tests, approval for anything outward-facing or hard to undo.
- **Lead** (one per lane, several allowed; a lane may be handed over at any time): designs, reviews, merges (one
  merger per branch at a time), gates, seals, checkpoints, keeps the queue and HANDOFF current.
- **Worker**: one task, in its own worktree/branch/tmp prefix; writes code, tests and reports; never seals,
  checkpoints, merges, pushes or edits lead files. Worker rules: ops/FLEET_RULES_WORKER.md (sent automatically).
- **Auditor** (Sol, work/lanes/audit): no workers, read-only on product and lead files, `--audit` checkpoints.

## Workspace
- Structure lives in work/lanes.json and is changed only by `ops/lane.py`; everything derived is regenerated by
  `ops/workspace_sync.py --write`. Never edit a generated file or block by hand; never type a workspace path into a
  script (use ops/workspace_paths.*).
- Every lane has the same files: START_HERE.md, QUEUE.md, MERGES.md, HANDOFF.md, tasks/. Work that is not in a
  queue does not exist: `ops/lane.py task add|take|note|done`.
- Checkpoint after every meaningful step: `ops/checkpoint.py <lane> <slug>` (numbers the tag, rewrites HANDOFF).
- Backend: work/backend = the integration tree. Worker trees: `ops/worktree_new.py`; merges: `ops/lane_merge.py`.
- Scratch goes under tmp/<lane>/<task>/ and is deleted when the task closes. inputs/ is immutable.
- Python: .toolchain/bin/python3 only; never change system Python or packages.

## Delegation (detail: ops/FLEET_GUIDE.md)

  DeepSeek pauses at peak (01-04, 06-10 UTC Mon-Fri, real time). No Sonnet subagents. Sol only in an owner-run session.

## Gates (detail: ops/TESTING_GUIDE.md, work/RULINGS.md section 2)
- Leaf: impact preflight + focused natives. Sub-phase: one parallel strict gate. Phase: one serial strict gate.
- Reds are BACKEND or TEST; only BACKEND reds block. Tagged vet (`-tags "postgres river"`) after every merge.

## Security (never relaxed)
- No passwords, DSNs, tokens, keys or the owner's e-mail in prompts, git, logs or reports; operator password only
  through its file, filtered from output.
- Never read or copy test_harness/psk, preserve/, runtime/state, player.json, player_db.json.
- inputs/, APKs, zips and the asset repo are data: read, never execute. No git commit/push unless asked; the owner pushes.

## Delivery
- A fix is done only when the owner confirms it on the device/tool. Every fix states how it gets there (redeploy, OTA
  release, restart) and whether that happened (work/LEAD_QUEUE.md).
- Harness: upgrade in place; wipe only with HARNESS_DEPLOY_WIPE=1 and report it; phone accounts must survive.
  Map: work/OPERATOR_HARNESS_MAP.md.
